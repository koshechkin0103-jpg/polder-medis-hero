# Polder Medis — интерактивный первый экран

**Живая версия:** <https://koshechkin0103-jpg.github.io/polder-medis-hero/>

Первый экран по макету `Дизайн.png` (2880×1440 @2x → база 1440×720 CSS px).
На фоне — голова из `Новое видео лицо.mp4` (4K, 215 кадров), которая поворачивается вслед за курсором.
`Видео.MOV` — старый 720p-исходник, `Кадры видео/` — тот же ролик покадрово (в сборке не используется).

## Запуск

Страница грузит видео через `fetch` (целиком в память), поэтому с `file://` она
не работает — нужен любой статический сервер. Встроенный вариант:

```
powershell -ExecutionPolicy Bypass -File tools\serve.ps1
```

и открыть <http://127.0.0.1:8765/>.

## Структура

```
index.html            разметка первого экрана
css/style.css         вёрстка; все размеры — в единице u = min(ширина/1440, высота/720) окна
js/main.js            слежение за курсором, загрузка видео, мобильный вариант
assets/card-photo@2x.png  фото в карточке, вырезано из «Элемент справа.png» (9…178 × 9…306 @2x)
assets/video/
  head-1x.mp4         1280×720 — лёгкий комплект (обычные экраны), 3.2 МБ
  head-2x.mp4         2560×1440 — тяжёлый комплект (retina, dpr ≥ 1.5), 7.2 МБ
                      оба: H.264, каждый кадр ключевой, зеркало и белый фон запечены
  poster-1x/2x.jpg    первый кадр — показывается, пока ролик грузится
tools/encode.ps1      перекодирование исходника (ffmpeg): делает 1x и, если исходник
                      ≥ 2560×1440, комплект 2x для retina
tools/diff-overlay.js вставить в консоль — наложит макет в режиме difference
tools/serve.ps1       локальный сервер
```

## Как измерялся макет

Все значения сняты пипеткой и bbox-ами чернил по PNG (canvas `getImageData`),
а не на глаз:

- **Шрифты** — сравнением ширины строки при совпадающей высоте букв.
  Заголовок/подписи/навигация: **Inter 400** (ширины совпали с точностью < 1 %).
  Навигация, категории и карточка в макете набраны чуть плотнее — воспроизведено
  отрицательным `letter-spacing`. Карточка: **Inter 600**. Логотип: **Antonio 700**
  (совпали и ширина, и толщина штриха; Bebas Neue уже, Anton — жирнее).
- **Цвета**: текст `#000`, приглушённые пункты меню `#b2b2b2`, «Groundworks»
  `#6b6b6b`, кнопка `#bb99c9`, фон `#fefefe`.
- **Градиент**: белый до y = 450, дальше профиль левой кромки макета (16 стопов)
  плюс радиальное сгущение к нижнему центру (в центре низа 216,179,220 против
  228,202,230 у кромки). Проверено численно: расхождение ≤ 3 уровня.
- **Адаптация под окно**: первый экран всегда равен окну браузера (100svh).
  Макет 1440×720 вписывается по меньшей стороне: в окне шире 2:1 сцена
  центрируется по горизонтали, в окне выше 2:1 (16:10 MacBook, панели браузера)
  шапка прижата к верху, нижний блок — к низу, голова центрируется в свободном
  месте, градиент отсчитывается от нижней кромки. При 1440×720 совпадает с макетом 1:1.
- **Видео**: голова в макете ровно в 2× от кадра, т. е. кадр 1280×720 стоит
  1:1 в CSS-пикселях базы 1440; позиция (71.5; −21.5) подобрана по bbox головы.
  В макете голова смотрит **вправо**, в исходнике — влево, поэтому ролик отзеркален.

Проверка: `tools/diff-overlay.js` в консоли на ширине 1440 — текст и градиент
чёрные (расхождения ≤ 1 px), светится только сама голова: в макете чуть иной
ракурс, чем в любом кадре ролика.

## Как работает слежение (`js/main.js`)

- Положение курсора относительно центра первого экрана → `nx, ny ∈ [−1; 1]`
  (мёртвая зона 3 %, дрожание < 1.5 px игнорируется).
- В ролике голова: вправо (0 с) → прямо (1.15 с) → влево (2.28 с) → прямо (3.2 с)
  → вправо (4.45 с). `nx` линейно переводится в целевое время внутри текущей
  половины ролика; чем дальше курсор от центра — тем сильнее поворот.
- Текущее время **догоняет** цель: скорость = `diff × gain`, но не больше
  **1.7 с видео за 1 с реального времени** (`CFG.maxSpeed`) и с ограниченным
  ускорением — резкий бросок мыши даёт плавный доворот без скачка кадров.
  Рядом с целью скорость затухает; при неподвижном курсоре цикл останавливается.
- Кадры сикаются по целым номерам (каждый кадр в файле ключевой), новый seek
  не отправляется, пока не пришёл `seeked`.
- Кадр рисуется в `<canvas>` с `mix-blend-mode: multiply`: белый фон исчезает,
  голова ложится на градиент. Напрямую у `<video>` Chrome/Safari теряют
  блендинг, поэтому canvas.
- **Вертикаль**: в исходнике голова не двигается вверх/вниз, поэтому
  вертикальная ось передаётся лёгким сдвигом головы (±9 u) с тем же сглаживанием.
  Если появится ролик с движением вверх/вниз, его нужно будет подключить
  как вторую ось (см. `CFG.halves`).
- Кнопка «Find out more» запускает «продолжение»: ролик проигрывается от
  текущего кадра до конца обычным воспроизведением, потом слежение продолжается
  во второй половине шкалы.
- Без hover (`(hover: none)`, телефоны): слежение выключено, композиция
  масштабируется пропорционально, по нажатию кнопки сразу играет продолжение.
- Стартовый стоп-кадр — поза как в макете (`CFG.startPose = 'mockup'`);
  `'front'` — лицо прямо.

## Видео

`tools/encode.ps1` (нужен ffmpeg: `winget install Gyan.FFmpeg`):

```
powershell -ExecutionPolicy Bypass -File tools\encode.ps1 -Source "Новое видео лицо.mp4"
```

- `hflip` + подъём фона: тона ≥ 236 → 255, ниже 222 не трогаются (плавное колено);
- `libx264`, `keyint=1` — все кадры ключевые, перемотка без рывков; crf 17 (1x) / 18 (2x);
- частота кадров берётся из исходника (4300/89 ≈ 48.3 fps);
- 1x = 1280×720, 2x = 2560×1440 (lanczos из 4K). `main.js` выбирает комплект по
  `devicePixelRatio` (порог 1.5) и грузит файл целиком в память.
